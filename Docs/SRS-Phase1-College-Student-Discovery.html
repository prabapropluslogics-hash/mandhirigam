3. Introduction and Purpose

3.1 Purpose

This SRS defines what Phase 1 of the Platform must do so that a developer can build it, a QA engineer can test it, and the client can see what is included. It is the controlled description of Phase 1 after a full review of the supplied requirement pack.

3.2 Audience

  • Client business owner and single point of contact, for scope and business-rule confirmation.
  • Project manager, for the readiness gate, exclusions, and change control.
  • UI/UX and frontend engineers, for public pages, the requirement form, and the admin panel.
  • Backend and database engineers, for the college model, recommendation, and lead state machine.
  • QA, for acceptance criteria, state transitions, and edge cases.
  • Deployment support, for the scheduler, file storage, mail, and environment dependencies. Full hosting is not part of the quoted build; see Appendix A.

3.3 Product intent preserved from the source

Phase 1 establishes the working foundation of an education-discovery platform. An administrator maintains complete college records. Students see that information, submit their requirements, receive suitable colleges, see scholarship information where it exists, and raise an enquiry. Every enquiry is offered first to Best Academy. If the required acceptance does not happen within the configured interval, the lead moves to the next active listing in the configured order.

The wider vision includes comparison tools, a college predictor, a separate course finder, reviews, community, blogs, AI-assisted publishing, partner-content workflow, college-representative accounts, and an SEO back office. Those items are not Phase 1. Section 33 lists them as excluded so they are not designed in passing.

6. Product Overview

The Platform is a responsive web application. Administrators maintain a structured catalogue of colleges. Students either browse that catalogue or submit a requirement form and receive a ranked shortlist. Scholarship records travel with the college into both the profile and the shortlist. An enquiry creates one lead. The lead is assigned to Best Academy before any later listing.

Phase 1 does not decide admissions, collect fees from students, or publish community opinion. Placement numbers, ranks, grades, and scholarship amounts are data entered by administrators from material the client provides. The system does not verify those claims with universities or regulators.

14.2 College Master

The admin college editor is one record with sections, not separate unrelated products: Profile, Location, Media, Courses, Admission, Fees, Scholarships, Facilities, Placement, Publication. Saving one section must not discard unsaved work in another section without a warning.

Courses, fee rows, scholarships, specializations, and gallery items are added as repeating rows. Admission, facilities, and placement are single blocks on the college.

14.3 Student requirement form

The form is one flow with a progress indicator and these steps, in order: Basic details, Academics, Course preference, College preference, Budget and scholarship, Review and consent. The student can move back without losing entries. Partial progress is kept in the browser only. Nothing is a lead until submit of this form or of an enquiry.

On submit, the API stores the submission, generates the recommendation set, and shows the shortlist. Leaving the page does not delete the stored submission. Phase 1 does not give the student a login to return to it later. The on-screen result remains available via a submission reference for the rest of that browser session. Proposed: the result URL contains an unguessable token valid for 72 hours so a refresh does not lose the shortlist. OQ-51.

14.4 Recommendation

Specified in Section 22. The public shortlist does not show the numeric score. It shows plain-language reasons, such as course match, location, fee within the stated maximum, and scholarship available. Platform Admin can see the score and reasons when opening the submission.

14.5 Enquiry

Enquiry from a profile concerns that college. Enquiry from a shortlist lets the student select one or more colleges in that set. The lead stores those colleges as interests. Routing does not send the lead to those colleges first.

The enquiry screen states, in plain language, that the request is received by the platform’s counselling desk and will be handled according to the platform’s response order. It must not say “your message has been sent to [selected college]” unless OQ-02 is answered by changing the business rule.

  1. Overview. Name, official name, short name, logo, gallery, location line, type, ownership, established year, affiliation, university, accreditation, recognition, NAAC, NIRF, website, public phone, public email, description, about.
  2. Courses. Active courses only. For each: name, category, type, study level, duration, mode, specializations, eligibility, required qualification, required subjects, entrance exam, admission process, intake, description, and a link to that course’s fees.
  3. Fees. Course-wise components, category where set, frequency, and total estimated fee. Hostel and other components appear in that breakdown.
  4. Scholarships. Active scholarships. Name, type, description, eligibility fields that were filled, benefit, dates, process, documents, provider, official link, terms, and the admin-authored student-experience note.
  5. Facilities. Only facilities marked Available or Not available. “Not provided” is omitted on the public page so an unknown facility is not presented as a denial.
  6. Placement. Whatever placement fields were filled, including recruiters and packages. If the statistics year is present, show it next to the figures.
  7. Admission. Process, eligibility, entrance exam, application process, dates, selection, counselling, documents, contact. If the application end date is before today in Asia/Kolkata, show “Application window ended” beside the dates. The record still remains visible.
  8. Location. Address, area, district, city, state, PIN, nearby city, campus note, coordinates if present, map or outbound map link.
  9. Enquiry. A persistent call to action.

Public and admin screens are usable at 360px width and at desktop width. Listing filters on a narrow screen sit in a panel that can be opened and closed. Tables in admin scroll horizontally rather than overflowing the page. Touch targets for primary actions are large enough to use without a mouse.

Field errors appear beside the field. Successful save and successful enquiry use a clear confirmation. A failed request leaves the user’s typed data in place and offers a retry. Toasts may be used for short admin confirmations. A toast is not the only confirmation of an enquiry; the confirmation screen and reference number are mandatory.

20. Validation Rules

20.1 Publish checklist

Publish is rejected, with a list of missing items, unless all of the following are true.

  • Display name, official name, description, college type, and ownership are present.
  • State, city, address, and PIN code are present.
  • At least one Active course exists with name, category, study level, study mode, and duration.

Scholarships, fees, placement, logo, gallery, NAAC, NIRF, and admission dates are not required to publish. Their absence is shown as not provided. This avoids blocking a college whose scholarship data is genuinely none, while still meeting the source rule that scholarship records are structured when they exist.

20.2 Cross-field rules

  • End dates are on or after start dates wherever both are entered.
  • Entrance exam name is required on a course only when entrance exam required is Yes.
  • Latitude and longitude are saved as a pair.
  • A Lead Operator must be linked to an active routing target.
  • Priority numbers are unique. Best Academy’s active row is priority 1.
  • Interval is a whole number of minutes from 5 to 10,080. Proposed bounds, OQ-24. Default 30.
  • Enquiry requires consent, name, mobile, email, and at least one published college.
  • A second enquiry with the same mobile number and the same set of college ids is rejected for 30 minutes after the first success, with the existing reference returned. A different college set is a new lead.

22. Recommendation Model

This section is proposed for sign-off. The source requires the system to use the student’s course, academic, eligibility, location, budget, college, and scholarship answers. It does not define ceilings, weights, or the empty-result rule. Do not treat the numbers below as approved until OQ-09, OQ-10, OQ-11, OQ-12, and OQ-13 are accepted or replaced. The matching service is built to this model only after that sign-off.

22.1 Candidate set

A candidate is a Published college with at least one Active course. Draft, unpublished, archived, and inactive courses are ignored.

22.2 Proposed gates

Student inputProposed effect
Preferred study levelHard gate. The college must have an active course at that level.
Course categoryHard gate. The college must have an active course in that category.
Maximum course fee, when filled, and the course has a total estimated feeHard gate. Total estimated fee must be less than or equal to the maximum. Courses with no total estimated fee stay in the set and are labelled “Fee not available”. They do not fail the ceiling.
Location, hostel, transport, ownership, college type, scholarship requiredNot hard gates in the proposed model. They change rank and they are explained on the card. Unknown facility data does not remove a college.

22.3 Proposed ranking

Among colleges that pass the gates, score the best active course that passes the gates. Show that course on the card and the count of other matching courses.

SignalPointsHow it is awarded
Course name30Full points if the interested-course text matches the course name or a specialization, case-insensitive, allowing a partial match of a word of at least four letters. Otherwise 0. Category is already a gate, so it is not scored again.
Study mode10Full points if the student chose a mode and the course mode matches. Full points if the student has no preference. Otherwise 0.
State10Full points if preferred state is empty or matches. Otherwise 0.
City10Full points if preferred city is empty or matches. Otherwise 0.
Budget fit15Full points if no maximum was given, or if the total estimated fee is within the maximum. 8 points if the fee is not available. 0 does not occur for a fee above the maximum because that course already failed the gate.
Scholarship15If the student answered No, award 15 and do not rank by scholarship. If Yes, award 15 when at least one visible scholarship is relevant, otherwise 0. Relevant means: college-wide or matching the chosen course, and not contradicted by a filled category, domicile state, or maximum income. Empty eligibility on the scholarship means it is treated as relevant.
Ownership and college type5Full points if each stated preference matches or was left as no preference. Split equally between the two preferences.
Hostel and transport5If the student marked Required, full points only when that facility is Available. If the student did not require it, full points.

Maximum score is 100. The shortlist shows up to 20 colleges with a score of at least 40, highest score first. Ties are broken by scholarship relevance, then by name. If none reach 40, the result is empty. The student is told that no college met the stated level, course, and fee inputs, and is offered edit and browse. The system does not backfill the empty list with unrelated colleges.

Academic marks, entrance rank, and eligibility paragraphs are stored and shown to the lead assignee. They are not an automatic eligibility decision in Phase 1, because the source does not define pass-mark formulas and eligibility text is unstructured. The profile still shows the college’s eligibility text so the student can judge it. Presenting a false “you are eligible” badge is out of scope.

Configuration: Best Academy interval 30 minutes, Listing B interval 30 minutes, Listing C inactive, Listing D interval 60 minutes. Enquiry at 10:00.

23.4 Concurrency and failure

  • The escalation job locks the lead row. If the status is no longer Assigned, the job does nothing.
  • Accept locks the lead row. If the status is no longer Assigned to that target, Accept fails with a clear message.
  • A failed email does not roll back assignment. The notification row stores the failure. The in-app notification still exists.
  • The public enquiry request does not wait for email delivery before returning the reference.

23.5 What assignees can see

The lead detail shows the reference, status, assignment time, escalate-at time, contact snapshot, requirement snapshot if the full form was used, interested colleges, recommendation reasons if any, and movement history. Lead Operators see history of the same lead only while they are the current assignee. After escalation they lose access. Platform Admin retains the full history. This protects student contact details from listings whose turn has ended.
